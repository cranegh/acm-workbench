# acm-workbench

我的算法学习与竞赛练习仓库，记录大学期间的日常刷题、VP、集训和比赛过程。代码以 C++ 为主，均来自自己手写的练习与积累。
除了简单的保存代码，本仓库还有维护代码模板和根据思路生成题解的功能。仓库配有两个 Codex 技能，帮助我自动化维护这个仓库，并按指令同步到 GitHub。

## 内容与导航

- [日常刷题](solutions/)：日常练习。
- [比赛记录](contest/)：VP、集训、比赛的记录
- [精选题解](editorials/)：记录关键观察、推导、复杂度、实现细节、和写题过程中的卡点与突破。
- [个人模板](template/README.md)：按基础算法、数据结构、图论、字符串、数学、动态规划和计算几何分类，附使用条件与调用说明。
- [模板打印手册](template/printable/ACM_Template.pdf)：方便训练和比赛前查阅的 PDF。

```text
acm-workbench/
├── README.md

├── contest/                   # 每场比赛一个目录

```

## 日常使用

平时继续按自己的习惯写题：单题放进 `solutions/`，整场 VP 或比赛放进 `contest/` 下对应的目录。需要整理时，在 Codex 中打开这个仓库，发送：

```text
$acm-maintainer 维护并同步
```

技能按以下流程处理：

1. **发现增量**：获取 GitHub 目标分支的最新提交，识别尚未同步的新增和修改，包括未跟踪文件、未提交修改以及本地已提交但未推送的内容。
2. **精选题解**：从这批题中选择 0–2 道值得沉淀的题。重点考虑关键转化、可迁移的思想、典型误区或有解释价值的优化，不凑篇数。
3. **按需补充模板**：检查是否出现现有模板没有覆盖的可复用内容，或有依据的小修正；普通重复练习通常不需要修改模板。
4. **检查并同步**：检查相关改动、执行必要验证，将本轮内容提交并推送到已配置的 GitHub 分支。

这些技能由指令触发，不会在保存文件后自行运行，也没有后台定时上传任务。同步需要本地 Git 仓库、可用的 GitHub 登录和已绑定的远端分支；遇到认证、冲突或不明确的提交范围时，会说明具体问题，不强制推送或覆盖工作。

## 题解怎么写

[editorial-style](.agents/skills/editorial-style/SKILL.md) 参考已有题解的表达方式：从朴素想法讲到关键观察，再落到实际代码。篇幅由题目决定，简单的思路可以短写，有必要复盘的题再展开。

参考文章：

- [ABC475 E：Quiz Competition — Trie](editorials/abc475-E.md)
- [ICPC 网络赛 K：MEX 候选压缩与复盘](editorials/icpc-2026-online2-K.md)

写题解时，技能可以询问我最初的想法、卡住的位置和最后的突破。个人经历以我的回答为准；记不清或没有补充时，就客观讲算法，不编造耗时、提交次数或比赛经历。

AI 辅助生成的题解需要我审阅。推导、复杂度和展示的代码应彼此对应，不能仅凭文件名或注释声称已经 AC。

## 模板怎么维护

模板保留我熟悉的结构、接口、变量命名和代码习惯。维护时默认不改；确有新内容，优先在相关文件中补充一小段实现或说明。

- 不为更新而更新，不重复收录已有算法。
- 不改变整体框架，不批量重命名、格式化或重构。
- 独立的新算法确实无法放入已有文件时，才在现有分类中增加文件。
- 对实际修改做针对性验证，并检查目录信息与打印手册是否需要同步；未完成的验证或手册更新应如实说明。

具体用法与适用条件见 [模板说明](template/README.md) 和各文件注释。模板中既有从历史代码提取的实现，也有后续补充；来源记录在模板目录中。

## 阅读与使用代码

这是持续积累的学习记录，历史文件中可能包含草稿、调试过程和不同版本。

多数题目是独立程序，应按题目单独编译、运行。模板中则有供复制使用的代码片段，不适合把整个仓库的 `.cpp` 一起链接成一个程序。使用前请核对题意、下标约定、数据范围和多测清空方式。

维护规则见 [acm-maintainer](.agents/skills/acm-maintainer/SKILL.md)。
